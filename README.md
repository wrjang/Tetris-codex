# Tetris MVP 실행 To-Do

이 문서는 [PRD.md](./PRD.md)의 MVP 범위를 구현하기 위한 작업 목록이다. 각 작업은 앞선 작업의 결과를 바탕으로 독립적으로 구현하고 검증할 수 있도록 작은 단위로 나누었다.

| Task | 산출물 | 완료 기준 |
|---|---|---|
| 1. 프로젝트 실행 환경 구성 | 브라우저에서 실행 가능한 최소 애플리케이션, 개발·빌드·테스트 스크립트 | 개발 서버에서 빈 게임 화면이 열리고, 빌드와 기본 테스트 명령이 오류 없이 완료된다. |
| 2. 게임 상수와 핵심 타입 정의 | 보드 크기(10 × 20), 좌표, 셀, Tetromino, 게임 상태 타입 및 상수 | 보드 크기와 게임 상태를 코드 한곳에서 참조할 수 있고 타입 검사 테스트가 통과한다. |
| 3. 빈 게임 보드 생성 | 10열 × 20행의 빈 보드를 만드는 순수 함수 | 생성된 보드가 정확히 20행과 10열이며 모든 셀이 비어 있음을 단위 테스트로 확인한다. |
| 4. 7종 Tetromino 모양 정의 | I, J, L, O, S, T, Z 블록의 모양·색상 데이터 | 각 종류가 정확히 4개의 블록 셀을 가지며 7종이 중복 없이 정의되었음을 단위 테스트로 확인한다. |
| 5. Tetromino 생성기 구현 | 7종 중 하나를 생성하는 순수 함수와 보드 상단 시작 좌표 규칙 | 반복 생성 시 반환값이 항상 7종 중 하나이고, 모든 블록이 유효한 시작 위치와 초기 회전 상태를 가짐을 테스트한다. |
| 6. 충돌 판정 구현 | 벽, 바닥, 고정 블록과의 충돌을 판정하는 순수 함수 | 보드 내부의 빈 위치는 허용하고 좌우 벽·바닥·고정 블록과 겹치는 위치는 거부하는 단위 테스트가 통과한다. |
| 7. 블록 스폰과 Game Over 판정 구현 | 새 블록을 활성화하고 스폰 충돌 시 종료 상태로 전환하는 로직 | 빈 보드에서는 블록이 정상 생성되고, 시작 위치가 막힌 보드에서는 즉시 Game Over가 되는 테스트가 통과한다. |
| 8. 좌우 이동 구현 | 충돌 판정을 사용하는 수평 이동 로직 | 빈 공간에서는 한 칸씩 이동하고 벽이나 고정 블록 앞에서는 위치가 변하지 않는 단위 테스트가 통과한다. |
| 9. 블록 회전 구현 | 활성 블록의 90도 회전 로직 | 회전 가능한 공간에서는 모양이 올바르게 바뀌고, 회전 후 충돌하는 경우 기존 상태가 유지되는 단위 테스트가 통과한다. |
| 10. 한 칸 하강과 Soft Drop 구현 | 활성 블록을 한 칸 아래로 이동시키는 공통 로직 | 하단 공간이 있으면 정확히 한 칸 내려가고, 바닥 또는 고정 블록과 충돌할 위치로는 이동하지 않는 테스트가 통과한다. |
| 11. 블록 고정 구현 | 더 내려갈 수 없는 활성 블록을 보드에 병합하는 로직 | 블록의 4개 셀이 정확한 보드 좌표에 기록되고 기존 고정 블록은 보존되는 단위 테스트가 통과한다. |
| 12. 완성 라인 탐지 및 제거 구현 | 가득 찬 행을 제거하고 위 행을 내리는 순수 함수 | 0개·1개·여러 개의 완성 라인에서 제거 수와 결과 보드가 정확하고 보드 높이가 20행으로 유지되는 테스트가 통과한다. |
| 13. 점수 계산 구현 | 한 번에 제거한 라인 수에 따른 점수 규칙과 누적 로직 | 0~4줄 제거별 점수가 명시된 규칙대로 계산되고 연속 제거 시 기존 점수에 누적되는 단위 테스트가 통과한다. |
| 14. 블록 고정 후 턴 전환 구현 | 고정 → 라인 제거 → 점수 반영 → 다음 블록 생성으로 이어지는 게임 턴 로직 | 블록이 더 내려갈 수 없을 때 위 순서가 한 번만 실행되고 다음 활성 블록이 생성되는 통합 테스트가 통과한다. |
| 15. 자동 하강 타이머 구현 | 일정 간격으로 하강 동작을 호출하는 게임 루프 | 게임 진행 중에만 설정된 간격으로 블록이 내려가며, 일시적인 중복 타이머 없이 종료 시 타이머가 정리되는 테스트가 통과한다. |
| 16. 키보드 입력 연결 | 방향키 기반 좌우 이동·회전·Soft Drop 입력 처리 | Left/Right 입력은 수평 이동, Up 입력은 회전, Down 입력은 Soft Drop을 각각 한 번 수행하며 페이지 기본 스크롤을 방지한다. |
| 17. 게임 보드 UI 구현 | 10 × 20 그리드와 활성·고정 블록 렌더링 | 데스크톱 브라우저에서 200개 셀이 안정적으로 표시되고 활성 블록과 고정 블록을 시각적으로 구분할 수 있다. |
| 18. 상태 UI 구현 | 현재 점수와 Game Over 표시 | 라인 제거 직후 점수가 화면에 반영되고 종료 상태에서 Game Over 안내가 표시되는 UI 테스트가 통과한다. |
| 19. Restart 기능 구현 | Restart 버튼과 전체 게임 상태 초기화 로직 | 언제든 Restart를 누르면 보드·점수·종료 상태·활성 블록·하강 타이머가 초기화되고 새 게임이 정확히 한 번 시작된다. |
| 20. 입력 반응성과 게임 흐름 통합 검증 | 핵심 사용자 시나리오를 검증하는 통합 테스트 | 스폰, 이동, 회전, 하강, 고정, 라인 제거, 점수 증가, Game Over, Restart의 전체 흐름이 자동화 테스트에서 통과한다. |
| 21. 데스크톱 브라우저 최종 QA | MVP 수동 점검 결과와 발견된 결함 수정 | 지원 대상 데스크톱 브라우저에서 설치·로그인 없이 시작할 수 있고, PRD의 F1~F12 및 성공 기준을 모두 직접 확인한다. |

## 완료 정의

모든 Task의 완료 기준을 충족하고 관련 테스트, 타입 검사, 빌드가 모두 통과하면 Tetris MVP 구현이 완료된 것으로 본다.
